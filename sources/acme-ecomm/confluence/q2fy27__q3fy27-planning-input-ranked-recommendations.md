### Submission Template
Please use the same shape we've asked for in past cycles, so the room can evaluate a proposal without needing a live follow-up meeting to understand it:
* **Problem Statement:** What pattern, metric movement, or VOC/seller-VOC signal motivates this, and where did you see it (which mart, experiment readout, VOC theme, or backlog cross-check)?
* **Target Metric:** The specific metric this should move, and roughly by how much.
* **Evidence Chain:** What you actually joined to get here, over what window, and what you ruled out along the way (a concurrent launch, a definitional change, a mix-shift, etc.) — so the room isn't left to redo that legwork live.
* **Proposed Ownership & Scope:** Who would run it and roughly what it touches.
* **Cost / Effort / Timeline:** Rough sizing for a Q3 window.
* **Trade-offs, if any:** If this is a clean win, say so plainly. If it isn't — if it trades a gain on one metric for a cost somewhere else — say that explicitly and bring both sides. Don't resolve a genuine trade-off unilaterally inside your own write-up; flag it as a decision the group needs to make together.

### Evaluation Criteria
We'll rank submissions using the same lens as always: cross-cutting reach (does this help one surface or several), strength and completeness of the evidence chain, expected impact on its target metric relative to effort and cost, and fit against the headwinds and dynamics summarized above. A proposal that only one vertical's own dashboard could have produced is still welcome — but one that surfaces something visible only when reading across verticals, surfaces, or feedback streams is especially valuable, since that's exactly the kind of pattern a single team's own reporting is structurally unlikely to catch on its own.
